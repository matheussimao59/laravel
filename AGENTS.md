# Orientacoes do projeto

## Entrega automatica no Git

- O usuario autorizou commit e push automaticos ao concluir cada alteracao solicitada, sem pedir uma nova confirmacao.
- Execute as verificacoes pertinentes disponiveis antes do envio. Informe quais nao puderam ser executadas; nao apresente verificacoes nao executadas como aprovadas.
- Inclua somente as alteracoes da tarefa. Preserve trabalho preexistente do usuario e nunca envie segredos, credenciais ou arquivos de ambiente.
- Confira o remoto e a branch, consulte atualizacoes do remoto e envie commits com mensagens claras para o upstream correspondente.
- Nao use force push nem reescreva o historico compartilhado. Se houver conflitos, divergencia ou falha nas verificacoes, resolva com seguranca ou informe o bloqueio antes de enviar.
- Ao finalizar, informe o commit enviado e o estado da sincronizacao. Push no GitHub nao significa que a API ja foi publicada.
- Informe quando a publicacao exigir migracoes ou outras etapas no servidor. Nao execute migracoes em producao sem autorizacao.
